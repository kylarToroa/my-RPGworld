# M2.0 视觉升级技术方案

日期：2026-11-10。项目：my-RPGworld。性质：技术审查与实施建议，尚未实现或验收 M2。

## 1. 基线、范围与结论

本地仓库实际位于 `D:\GitHub`。开始时工作区干净，分支为 `feat/m2-content-expansion`。本地 `main`、`origin/main` 与 HEAD 均为 `a61c2353342ccb06ce8b8d62586a6babd44c17ec`。通过匿名 Node HTTPS 请求 GitHub 公开 commits/main API，获得 HTTP 200 与同一 SHA，确认核验时远程 main 没有更新。随后从 main 创建并切换到 `feat/m2-visual-upgrade`。

普通 Git fetch 曾因 Windows Schannel 初始化失败、OpenSSL 缺少证书链失败，未成功 fetch；上述最新性结论来自公开 API 与完整提交哈希比对，不是仅凭本地远程跟踪分支。没有关闭 TLS 校验，没有读取系统凭据，没有推送、部署或合并。

**建议保留 Phaser + TypeScript + 数据驱动世界 + HTML 阅读界面的架构，在现有 16×16 格子体系上逐步升级美术。** 当前主要限制是占位素材、地图装饰层级、固定角色帧布局和 UI 细节，并不需要重写引擎。M2.0 聚焦现有小镇、图书馆、三个角色与阅读体验；新增地图、NPC、内容玩法、战斗、账号和后端均不在此方案范围。

本次检查覆盖应用源码、世界配置、地图结构、资源清单及生成脚本、内容构建、样式、现有测试与维护约定。当前模型不能读取图片，因此图像文件尺寸与代码结构已核实，实际画面美感、遮挡效果与真机体验仍需后续视觉评审。仓库已有截图不能作为本轮新测试通过的证据。

## 3. 推荐美术方向

采用“温暖、安静、易探索的像素书屋小镇”：户外以低饱和草绿、土路和暖木色为主；室内以木色、纸色和局部暖光区分区域。交互点使用统一的浅金强调色，危险/不可达反馈保留形状与文字，不只依赖颜色。

这是建议方向，尚未获得美术定稿。先用同一机位的小镇入口、图书馆书架、角色四向和文章弹窗形成一组对照稿，再批量产出资源。画面重点应是角色、门、书架和道路；装饰丰富度不能压过内容入口。

保留清晰像素轮廓，不用全屏模糊、重 Bloom 或持续屏幕抖动掩盖占位素材。中文正文继续用易读系统字体，不为“像素风”牺牲长文阅读，也不默认引入大型中文像素字体包。

## 5. 地图与渲染设计

建议采用明确的显示层级：地面 → 地面装饰/投影 → 按脚底排序的角色与高物件 → 必要的顶层屋檐/树冠 → 交互标记 → HTML UI。世界光色不应压暗 HTML 阅读内容。

当前 marker depth=5000，而 above=100000；加入树冠后目标标记会被挡。实施时统一管理 depth 常量，规定标记、阴影、人物、顶层装饰的位置，避免各处散落魔法数字。

不是所有树冠都应该永远压在人上面。完全不可进入的建筑可用固定前景；允许玩家从前后经过的树/家具应按脚底 Y 排序，或由美术拆分并严格约定可行走区。第一批地图尽量保留既有通路，仅增加纯装饰；复杂排序先选一个物件验证，不全面改地图格式。

网格解析目前只识别顶层 collision 的普通 data 数组，且缺少该层时会视作全通行。M2 编辑规范继续限定有限、正交、16×16、无分组 collision、无无限地图 chunks；实施新图块之前增加对图层存在性、data 长度、地图类型、tileset 名称和 GID 范围的校验。不能让 Tiled 中“看起来正常”的地图悄悄失去碰撞。

镜头首批保留现状。实测横竖屏、DPR、窗口尺寸临界点后，再决定是否调整 zoom 阈值。若使用缓动，仍须保持最终像素对齐，并验证点击世界坐标；不把镜头变化和地图层级重构放在同一交付批次。

## 6. 素材交付合同

资源入口继续统一使用 [资源清单](<D:/GitHub/world/assets.json>)；运行时代码、实体与场景仅引用资源 ID，不硬编码图片路径。Tiled 嵌入的 image 元数据是现有编辑器约定，仍需与清单和图块尺寸一致，不应声称它已完全消除路径重复。

首批资源包建议：

- 一套户外与室内图块：16×16 基础网格，覆盖道路/草地边界、墙与屋顶转角、水岸、书架/桌椅/植物；额外装饰使用透明背景。
- 三套角色：player、villager、librarian；兼容版每张48×64、单帧16×16、下左右上四行、站立/步态A/步态B三列。先验收所有朝向，再扩充帧数。
- 可选第二批：水波3–4帧、灯火3–4帧、角色待机2–3帧；这些数量是制作建议，现引擎尚不支持自动按此合同播放。
- 一份资源台账：作者、来源、授权/委托证明、修改记录与版本。仅使用原创、委托原创或授权明确且符合项目约定的非商业游戏素材；不引入付费服务或擅自购买。

现 tileset PNG 为128×48、8列，地图声明20个有效 tile。只在保持 tile 索引、尺寸和透明语义一致时可直接换图；扩展图块需要更新 tilecount/image尺寸、地图 GID 和校验。三个角色若改为16×24/32，脚底锚点原则可复用，但上半身会超出当前格子点击区域，不能只改 frameHeight 就判定完成。M2.0 首选16×16以控制风险。

动画建议最终由可选的纯数据元信息描述方向、idle帧、walk帧和帧率；缺省继续使用旧四向三帧规则。静态道具与角色动画分开建模，因为现代码会给所有 sprites 注册 walk。扩展字段先在 Schema 中声明，并补帧号范围/图片尺寸检查，再让配置使用；不提前搭建通用动画编辑器。

占位图和地图生成脚本会覆盖同名资源。正式美术落地后应明确标记为仅用于原型，避免维护者执行 gen:art/gen:maps 覆盖手工结果；本轮没有运行这些生成命令。

## 7. UI 与交互方案

基础视觉统一可直接从 [共享样式](<D:/GitHub/public/site.css>) 开始，但涉及键盘、关闭时机和 Promise 完成的变化必须检查 [UI 实现](<D:/GitHub/src/web/ui.ts>) 与 ActionRunner 的 busy 锁。

- 以同一套颜色、间距和边框变量覆盖游戏与独立页面；正文保持合理行宽与≥16px默认字号，长链接、代码、表格在窄屏内可读。
- 对话框增加短屏最大高度和内部滚动，保留继续、选项、Esc；可见的“继续”按钮比只显示 ▼ 更容易理解。M2.0 不默认引入逐字打字效果，避免多一次点击、朗读器重复播报和选择时序回归。
- 弹窗实现焦点约束、关闭后焦点恢复、列表切文章后的合理聚焦；保留滚动区可见焦点。现 aria-modal=true 本身不能阻止 Tab 进入背景导航。
- 为内容请求增加请求序号或取消机制：关闭/切换后过期结果不能覆盖新内容。当前异步回调没有此保护，这是风险审查发现，不代表已有用户复现报告。
- 手机导航和文章标题避免挤压关闭/返回按钮；safe-area 覆盖顶部、底部，横屏和短屏也验收。交互提示分层展示，不在窄屏永久塞入整句桌面说明。
- 交互高亮只作辅助，继续保留 HTML 提示与不可达文字。扩大高角色点击区若要实施，需要独立于碰撞占格设计，并解决重叠对象选择优先级。
- 减少动态偏好统一传递到 Phaser；当前 CSS 仅关闭继续箭头和 toast 动效。新增淡入、粒子、待机等应有静态退路。

补充内容风险：独立文章用 base 指向站点根目录，未来若加入文内 #fragment/目录跳转需分别验证弹窗与独立页，不应直接添加目录组件。首页与独立页标题来源也需在品牌升级时统一。这些不要求本轮扩大到内容功能开发。

## 8. 实施结构与风险控制

不做引擎替换或大规模重构。可在实施中从 WorldScene 有限提取“资源与动画注册”“场景显示对象/特效生命周期”“层级常量”三个职责；输入、寻路、碰撞和存档仍由现有逻辑负责。可视配置只描述风格、资源 ID、动画和轻量环境参数，不改变 action 行为语义。

| 风险 | 原因 | 控制措施 |
|---|---|---|
| 门或书架失效 | 美术位置与实体占格不一致 | 初批保留实体坐标/范围/trigger；叠加调试格检查；真实点击回归 |
| 老存档落点变化 | 改 collision/场景ID/出生点 | 首批冻结这些字段；必要修改单独审查与旧存档用例 |
| 树冠遮人或标记消失 | 固定 above 与 Y 排序混用 | 固定前景和高物件分开；四周行走及点击截图验收 |
| 换帧越界或脚滑 | 帧数/布局硬编码，步速与动画关联 | 先等规格换图；后续配置化并校验帧号；不同时改步速 |
| UI锁定无法解除 | 为动效延迟关闭或破坏 Promise | 保留返回/关闭语义；连续操作、Esc、快速切换内容测试 |
| 内存/帧率劣化 | 旧粒子、计时器、tween 没有销毁 | 场景级统一清理；20次进出场景观察对象和内存趋势 |
| 加载失败扩大 | 目前全部 sprites/tilesets 首次预加载 | M2小资源包保持简单；必需资源失败走现有内容入口，装饰缺失可降级 |
| 路径部署回归 | 新资源硬编码根路径或绕过清单 | 继续相对路径；在 /my-RPGworld/ 子路径验收 |

## 9. 建议实施批次

1. **M2.0-A：基线与视觉规范。** 在可运行环境重跑 M1 测试、固定桌面/手机截图与资源体积，确定色板、像素比例、透明规则、层级合同。交付一页风格对照稿与素材清单；不改玩法。
2. **M2.0-B：UI 与显示反馈。** 共享主题、阅读/手机布局、焦点、请求过期保护、脚底阴影、目标反馈、减少动态支持。独立验收后再做地图美术。
3. **M2.0-C：同规格美术替换。** 先完成一个小镇局部和一组书架样例，再替换两张现有地图和三个角色；保持逻辑坐标，补资源校验。
4. **M2.0-D：层级与可选微动画。** 透明前景、必要的 Y 排序物件、少量水波/灯火/待机。按实际资源和性能决定是否全部纳入；不以炫技效果阻塞基础视觉交付。
5. **最终回归与人工试玩。** 完整 M1 功能 + 视觉/无障碍/性能验收；每批可以独立回退。实现期通过 PR 交付；合并与正式部署仍需站长确认。

优先级：B 的可读性/交互可靠性与 C 的整体素材质量最高；D 的氛围效果可裁剪。工期取决于原创美术资源交付和视觉返工，不在素材尚未定稿时给出确定日期。

## 10. 验收标准与当前验证状态

### 功能保留

必须保留键盘移动、点击寻路、碰撞、不可达反馈、自动靠近互动、NPC转向、对话选项、室内外进出、分类书架与草稿过滤、文章阅读与返回列表、独立页面/子路径、?open入口、刷新存档、坏存档/禁用存储回退、回到起点和清除存档按钮。保留现有测试，不用删除断言换取通过。

现有测试为5个单元测试文件及浏览器冒烟脚本。E2E 覆盖1280×720桌面、390×844触屏、独立页和禁用存储，但截图只是输出，没有像素差异断言。部分用例名称强于断言：阅读滚动只检查角色没移动，碰撞只检查坐标下限，清除存档没有直接验证存储内容。M2 增补这些实际行为断言，而不是仅扩充测试名称。

### 新增视觉与交互验收

- 视口：至少1280×720、1920×1080、390×844、320×568及手机横屏；DPR1/2/3与常用浏览器缩放。桌面/移动端人工试玩，不把浏览器触屏模拟当真机全部通过。
- 固定机位：小镇起点/门口/树旁/水边、图书馆书架/出口、对话选项、文章长标题/长文、独立内容页。
